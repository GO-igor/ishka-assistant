# Запуск Ишки на Mac (Apple Silicon: M1–M4)

Понадобятся два окна Терминала:
1. В первом работает **сервер с моделью** (llama.cpp).
2. Во втором работает **чат** (`chat.py`). Он передаёт вопросы модели, а ответы на них берёт из настоящих данных: расписания, аудиторий и т. д.
   Промпт для модели `chat.py` собирает сам, ровно как при обучении, и отправляет серверу готовым.

Ошибка `zsh: command not found: llama-server` значит одно: llama.cpp ещё не установлен. Установка описана в шагах 1–2.

---

## Шаг 1. Установить Homebrew (один раз)

Homebrew — это «магазин» программ для Терминала. Проверь, есть ли он:

```bash
brew --version
```

Если в ответ пришло `command not found`, установи Homebrew:

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Установщик попросит пароль от Mac (символы при вводе не видны, так и должно быть) и нажать Enter.
**В конце он напишет «Next steps»: выполни команды из этого блока.** Обычно это две строки:

```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
```

Снова проверь `brew --version`: должна появиться версия.

## Шаг 2. Установить llama.cpp (один раз)

```bash
brew install llama.cpp
llama-server --version
```

Если вторая команда напечатала версию, всё готово.

## Шаг 3. Скачать модель с Google Диска

1. Открой drive.google.com, папку **Мой диск → ishka**.
2. Скачай файл `*.gguf` (~2.5 ГБ) и `Modelfile`. Modelfile нужен только для Ollama.
3. Создай папку `ishka-model` в домашней папке и перенеси туда `.gguf`.
4. Проверь в Терминале, как точно называется файл:

```bash
ls ~/ishka-model
```

Дальше вместо `ИМЯ.gguf` подставляй это имя. Можно переименовать файл в `ishka-Q4_K_M.gguf`, тогда команды ниже подойдут без изменений.

## Шаг 4. Запустить сервер с моделью (окно 1)

```bash
cd ~/ishka-model
llama-server -m ishka-Q4_K_M.gguf --jinja -c 16384 --port 8080
```

- `--jinja` включает шаблон чата Qwen в самом сервере. `chat.py` собирает промпт сам, но `--jinja` нужен для проверки `diag_server.py` (шаг 7).
- `-c 16384` задаёт память диалога: 16 тысяч токенов, из них ~2,5 тысячи занимает описание инструментов. Это около 2,5 ГБ памяти. Без этого параметра llama.cpp берёт максимум модели (262 тысячи токенов) и не помещается в 16 ГБ.

Когда в конце появится строка `server is listening on http://127.0.0.1:8080`, сервер готов.
**Не закрывай это окно**: пока оно открыто, модель работает. Остановить сервер: Ctrl+C.

Проверка: открой в браузере http://localhost:8080. Там простой чат с моделью, но **без доступа к расписанию**, поэтому на вопросы о парах он ответит неправильно. Для настоящей проверки используй шаг 6.

## Шаг 5. Скачать проект и подготовить Python (один раз, окно 2)

Открой второе окно Терминала: Cmd+N.

```bash
cd ~
git clone https://github.com/GO-igor/ishka-assistant.git
cd ishka-assistant
python3 -m venv .venv
source .venv/bin/activate
pip install jinja2
```

- Если Mac предложит установить «инструменты разработчика» (нужны для `git`), соглашайся и повтори команды после установки.
- Без git: на странице репозитория на GitHub нажми *Code → Download ZIP*, распакуй архив в домашнюю папку и перейди в получившуюся папку командой `cd ~/ishka-assistant-main`.

## Шаг 6. Поговорить с Ишкой (окно 2)

```bash
cd ~/ishka-assistant
source .venv/bin/activate
python chat.py --subgroup 2 --english "Аксёнова Н. В."
```

Без `source .venv/bin/activate` будет `command not found: python`: эту строку нужно выполнять в каждом новом окне Терминала.

Подставь свою подгруппу и своего преподавателя английского: Аксёнова Н. В., Ануфриева Т. Н., Пичугова И. Л. или Ростовцева В. М.
Появится приглашение `ты>`: пиши вопрос и жми Enter. Строки вида `[get_schedule {...}]` показывают, какой инструмент вызвала модель.
Выход из чата: Ctrl+D.

Что попробовать:

| Вопрос | Что должно произойти |
|---|---|
| `привет` | ответ текстом, без инструмента |
| `что завтра по парам?` | `get_schedule` с `day: tomorrow` |
| `как найти 529 аудиторию в 19 корпусе` | `find_room` |
| `успею из ГК в МКЦ к следующей паре?` | `check_travel_time` |
| `запиши дз по матлогу: решить №5–10` | `add_homework` |
| `добавь экзамен по питону 15 января в 9:00` | `add_exam` |
| `напомни мне оплатить общагу` | уточняющий вопрос «когда напомнить?» |
| `объясни рекурсию` | объяснение текстом |

Время можно подменить для проверки: `--now "2026-10-12 09:50"`.
Д/З, заметки и напоминания тестовый бэкенд хранит только до закрытия `chat.py`.

**Записывай фразы, на которых Ишка ошибается**: из них соберём примеры для следующего обучения.

## Шаг 7. Проверка модели, если Ишка отвечает странно (окно 2)

Сервер из шага 4 должен работать. Чат закрой (Ctrl+D) и запусти с теми же подгруппой и преподавателем, что в шаге 6:

```bash
cd ~/ishka-assistant
source .venv/bin/activate
python diag_server.py --subgroup 2 --english "Аксёнова Н. В."
```

За 2–5 минут скрипт задаст модели вопросы из шага 6 ровно в том виде, в каком она видела диалоги при обучении: сразу после вопроса и после ответа инструмента. Для сравнения каждый вопрос уходит ещё и так, как его отправлял старый `chat.py`. В конце будет **«Итог»**: в порядке ли сама модель или проблема в её весах. **Пришли весь вывод целиком.**

Если «Итог» пишет, что дело в весах `.gguf`, открой ноутбук с GitHub в Colab заново и выполни раздел 10 «Проверить LoRA с Диска»: он покажет, хорошо ли модель отвечает до экспорта, и при необходимости заново сделает `.gguf`.

## В следующий раз

Устанавливать ничего не нужно. Окно 1: шаг 4. Окно 2: шаг 6.

Если я написал, что обновил проект на GitHub, скачай обновления в окне 2: `cd ~/ishka-assistant && git pull`, затем `source .venv/bin/activate && pip install jinja2`.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `command not found: brew` после установки | выполнить две строки из «Next steps» шага 1 и открыть новое окно Терминала |
| `command not found: llama-server` | шаг 2: `brew install llama.cpp` |
| `failed to open ... .gguf` / `No such file` | файл не в этой папке или имя другое: `ls ~/ishka-model`, затем `cd` туда; можно перетащить файл в окно Терминала, и путь вставится сам |
| сервер падает с ошибкой памяти | проверить, что указан `-c 16384` (можно `-c 8192`); закрыть тяжёлые программы |
| `exceeds the available context size` | обнови проект (`git pull`): новый `chat.py` сам забывает старые реплики. Сервер перезапусти с `-c 16384` |
| в чате строка `[повтор ...: прошу ответить без инструментов]` | модель зациклилась на одном вызове, `chat.py` остановил её и попросил ответить словами. Запиши такую фразу: это пример для следующего обучения |
| после `Не получилось ответить` строка `[сырой ответ модели: ...]` | это то, что модель написала на самом деле. Запусти шаг 7 и пришли его вывод |
| `zsh: command not found: python` | не активировано окружение: `cd ~/ishka-assistant && source .venv/bin/activate` |
| `address already in use` | сервер уже запущен в другом окне; или запусти на другом порту: `--port 8081` и `python chat.py --url http://localhost:8081 ...` (так же `diag_server.py --url ...`) |
| `[сервер ... не отвечает ...]` в chat.py | сервер в окне 1 не запущен или ещё грузится: дождись `server is listening` |
| `ModuleNotFoundError: No module named 'jinja2'` | не активировано окружение или не установлен jinja2: `source .venv/bin/activate`, затем `pip install jinja2` |
| хочу через Ollama | `pip install openai`, затем `python chat.py --api openai --url http://localhost:11434/v1 --name ishka ...` |
| `Преподаватель английского не найден` | ФИО из списка в шаге 6, можно просто фамилию: `--english Аксёнова` |
| первый ответ идёт 5–15 секунд | нормально: модель читает описание 18 инструментов, дальше быстрее |
| Ишка отвечает текстом про расписание, не вызывая инструмент | запиши фразу (пример для обучения); если так на всё подряд — шаг 7 |
