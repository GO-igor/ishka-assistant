# Быстрый запуск Ишки на Mac (всё уже установлено)

Эта памятка для тех, у кого уже стоят Homebrew и llama.cpp, лежит папка `~/ishka-model` с моделью и склонирован проект `~/ishka-assistant`.
Если что-то из этого нет, начни с [RUN_MAC.md](RUN_MAC.md): там установка с нуля.

Нужны два окна Терминала (Cmd+N открывает новое).

---

## Окно 1. Сервер с моделью

```bash
cd ~/ishka-model
llama-server -m ishka-Q4_K_M.gguf --jinja -c 16384 --port 8080
```

Подставь своё имя файла, если оно другое (`ls ~/ishka-model`). Готово, когда появилась строка `server is listening on http://127.0.0.1:8080`.
**Окно не закрывай**: пока оно открыто, модель работает. Остановить: Ctrl+C.

## Окно 2. Чат

Если я писал, что обновил проект, сначала скачай обновления:

```bash
cd ~/ishka-assistant
git pull
```

Потом запусти чат:

```bash
cd ~/ishka-assistant
source .venv/bin/activate
python chat.py --subgroup 2 --english "Аксёнова Н. В."
```

Подставь свою подгруппу и своего преподавателя английского. Или войди под аккаунтом (подгруппа и английский возьмутся из него):

```bash
python chat.py --login ivanov
```

Появится `ты>`: пиши вопрос и жми Enter. Выход: Ctrl+D. Остановить длинный ответ: Ctrl+C.

Полезные флаги: `--now "2026-10-12 09:50"` подменяет время, `--debug` показывает вызовы инструментов и вероятность вызова.

## Если не заработало

| Симптом | Что делать |
|---|---|
| `[сервер ... не отвечает ...]` | окно 1 закрыто или сервер ещё грузится: подожди `server is listening` |
| `command not found: python` | в этом окне не активировано окружение: `cd ~/ishka-assistant && source .venv/bin/activate` |
| `command not found: llama-server` | llama.cpp не установлен: шаг 2 из RUN_MAC.md |
| `failed to open ... .gguf` | неверное имя файла или папка: `ls ~/ishka-model` |
| `address already in use` | сервер уже запущен в другом окне, или возьми другой порт: `--port 8081` и `python chat.py --url http://localhost:8081 ...` |
| `Не читается список запретных фраз` | в `db/blocklist.json` ошибка (чаще всего забыта запятая или кавычка): исправь файл, чат покажет место |
| Ишка отвечает странно | `python diag_server.py --subgroup 2 --english "Аксёнова Н. В."` и пришли весь вывод; подробнее в шаге 7 RUN_MAC.md |

# Как проверить «Умного старосту»

Староста рассылает группе Д/З, мероприятия и напоминания, студенты видят это в утреннем брифинге отдельной строкой «📢 От старосты».
Проверка занимает минут десять. У неё две части:
- **Часть А** не требует модели: проверяется сама логика (кто что получает). Сервер из окна 1 для неё не нужен.
- **Часть Б** проверяет всё вместе с моделью, как будет в жизни. Модель должна быть обучена **после 10 октября**, иначе она не знает инструментов рассылки
  (вторая модель их не знает: вход, аккаунты и хранение данных с ней работают, а «разошли группе» не сработает).

Чтобы не мусорить в настоящей базе, всё делается в отдельной тестовой базе. Эту строку нужно выполнить **в каждом окне**, где идёт проверка:

```bash
cd ~/ishka-assistant
source .venv/bin/activate
export ISHKA_DB=~/ishka-test.sqlite
```

## Шаг 1. Завести тестовые аккаунты

Один староста и два студента в одной группе, но в разных подгруппах (подгруппы нужны, чтобы проверить рассылку только части группы):

```bash
python accounts.py add petrova --group 8К51 --role starosta --name "Анна Петрова" --password starosta1
python accounts.py add ivanov --group 8К51 --subgroup 2 --english Аксёнова --name "Иван Иванов" --password student1
python accounts.py add sidorov --group 8К51 --subgroup 1 --name "Пётр Сидоров" --password student2
python accounts.py list
```

Ожидается список из трёх строк: староста `petrova`, студент `ivanov` (подгруппа 2), студент `sidorov` (подгруппа 1).
Для проверки пароли простые. Для настоящих аккаунтов пароль не пишут в команде: убери `--password`, и он спросится скрыто.

## Часть А. Без модели

Скрипт делает то же, что сделала бы модель, когда староста пишет в чат, но вызывает бэкенд напрямую. Время в нём зафиксировано на понедельник, 12 октября 2026, 08:00.

```bash
PYTHONPATH=. python3 - <<'EOF'
import datetime as dt
from store import Store
from backend import Backend
st = Store()
def be(login):
    acc = st.account(login=login)
    return Backend(dt.datetime(2026, 10, 12, 8, 0), st.profile(acc), st, acc["id"])
head, s2, s1 = be("petrova"), be("ivanov"), be("sidorov")
print(head.group_add_homework("матлог", "№5–10", due="friday"))
print(head.group_add_event("Хакатон", "2026-10-17", time="10:00", place="МКЦ"))
print(head.group_create_reminder("взять зачётки", in_days=1, subgroup=2))
print("студент пытается разослать:", s2.group_add_homework("физика", "x"))
print("БРИФИНГ ivanov (подгруппа 2):", s2.get_daily_brief().get("from_starosta"))
print("БРИФИНГ sidorov (подгруппа 1):", s1.get_daily_brief().get("from_starosta"))
EOF
```

Что должно получиться (порядок строк именно такой):

| Строка вывода | Что значит |
|---|---|
| `{'ok': True, 'subject': 'Математическая логика и теория алгоритмов', 'due': '2026-10-16', ..., 'recipients': 2}` | Д/З ушло двум студентам группы. Название предмета бэкенд узнал сам, срок «пятница» превратил в 16 октября |
| `{'ok': True, 'title': 'Хакатон', 'date': '2026-10-17', 'time': '10:00', 'place': 'МКЦ', 'days_left': 5, 'recipients': 2}` | мероприятие ушло обоим |
| `{'ok': True, 'fire_at': '2026-10-13 08:00', 'recipients': 1, 'subgroup': 2}` | напоминание ушло **одному** человеку: только второй подгруппе |
| `студент пытается разослать: {'error': 'not_starosta'}` | обычному студенту рассылка запрещена |
| `БРИФИНГ ivanov ...` | **три** пункта: напоминание, Д/З, мероприятие |
| `БРИФИНГ sidorov ...` | **два** пункта: Д/З и мероприятие, напоминания второй подгруппы у него нет |

Если все шесть строк такие, логика рассылки работает. Результат повторяется: перед повторным запуском удали тестовую базу (последний шаг) и заведи аккаунты заново, иначе рассылки задвоятся.

## Часть Б. С моделью

Окно 1: запусти сервер (см. начало памятки). Окно 2: выполни три строки подготовки выше (`cd`, `source`, `export`).

### Б1. Староста рассылает

Войди как староста. Время зафиксировано, чтобы «пятница» и «завтра» означали одно и то же при каждой проверке:

```bash
python chat.py --login petrova --now "2026-10-12 08:00"
```

Спросит пароль (`starosta1`, символы не видны). Ишка поздоровается: «Привет, Анна Петрова! Группа 8К51, ты староста: можешь отправлять группе Д/З, мероприятия и напоминания.»
Если написано просто «Группа 8К51.» без слов «ты староста», у аккаунта роль студента: `python accounts.py edit petrova --role starosta`.

Пиши по очереди:

| Что написать | Что должно появиться |
|---|---|
| `выдай группе дз по матлогу: №5–10 к пятнице` | строка `[group_add_homework {...}]` с предметом, заданием и сроком `friday`, потом ответ вроде «Отправил группе: срок пятница 16 октября» |
| `разошли всем: хакатон в субботу в 10:00, МКЦ` | `[group_add_event {...}]` с датой `2026-10-17`, временем и местом, потом подтверждение |
| `напомни второй подгруппе завтра в 9:00 взять зачётки` | `[group_create_reminder {...}]` с `subgroup: 2`, потом подтверждение, что дойдёт второй подгруппе |

Слова ответа у модели могут чуть отличаться, важно другое: вызов нужного `group_...` в квадратных скобках, правильные аргументы и в ответе число получателей (2 для первых двух, 1 для напоминания).
Если вместо вызова Ишка просто отвечает текстом «разослала», а строки `[group_...]` нет, модель не знает инструментов рассылки (обучена до 10 октября). Тогда проверяй часть А и см. «Если что-то не так» ниже.

Выйди: Ctrl+D.

### Б2. Студент второй подгруппы видит рассылки

```bash
python chat.py --login ivanov --now "2026-10-12 08:00"
```

Пароль `student1`. Напиши по очереди:

| Что написать | Что должно появиться |
|---|---|
| `[авто] утренний брифинг` | в брифинге отдельная строка **«📢 От старосты»** с тремя пунктами: напоминание про зачётки, Д/З по матлогике до пятницы, хакатон в субботу в 10:00 в МКЦ. Д/З старосты в обычном списке Д/З брифинга не дублируется |
| `что задали?` | в списке Д/З есть «№5–10» по матлогике, помеченное как от старосты |
| `какие мероприятия на неделе?` | в списке есть «Хакатон» от старосты (рядом могут быть примеры из `db/events.json` с пометкой «пример»: это не рассылка) |
| `мои напоминания` | в списке есть «взять зачётки» от старосты |

Выйди: Ctrl+D.

### Б3. Студент первой подгруппы не видит чужого

```bash
python chat.py --login sidorov --now "2026-10-12 08:00"
```

Пароль `student2`. Напиши `[авто] утренний брифинг`: в строке «📢 От старосты» должно быть **два** пункта (Д/З и хакатон), без напоминания про зачётки: оно было только для второй подгруппы. Проверь и `мои напоминания`: зачёток там быть не должно.

### Б4. Студент не может рассылать

Всё ещё под `sidorov` напиши `выдай группе дз по физике: задача 5`. Строки `[group_add_homework ...]` быть не должно: у студента инструментов рассылки в промпте нет. Ишка ответит текстом (что-то вроде «рассылать может только староста»).
Если модель всё-таки вызвала инструмент, бэкенд его отклонит ответом `not_starosta`, и в базу ничего не попадёт.

### Б5. Когда срок прошёл

Проверка, что просроченное из брифинга уходит. Войди студентом второй подгруппы, но уже во вторник, после времени напоминания:

```bash
python chat.py --login ivanov --now "2026-10-13 09:30"
```

Напиши `[авто] утренний брифинг`: напоминания про зачётки уже нет (его время, 9:00 вторника, прошло), а Д/З и хакатон на месте. Теперь войди с `--now "2026-10-18 08:00"`:
в брифинге от старосты пусто, `что задали?` без «№5–10», потому что срок Д/З (пятница) и хакатон (суббота) уже прошли.
Настоящие уведомления «в нужную минуту» появятся, когда будет написан планировщик (GUIDE.md, шаг 6): пока напоминание видно в брифинге и в `мои напоминания` до своего времени.

# Как проверить удаление и лимиты

Ишка показывает заметки, напоминания, Д/З, дедлайны и экзамены списком с номерами. Удалить можно по номеру («удали 2»),
по словам («удали заметку про флешку») или все сразу: тогда Ишка сначала переспросит, а удалит после «да».
Номера берутся из последнего показанного списка и после удаления не сдвигаются: «и 4 тоже» — та же четвёртая.
Лимит — 10 заметок и 10 своих напоминаний: на одиннадцатую Ишка покажет список и предложит удалить старую.
Рассылку старосты студент убирает только у себя, а староста отменяет её для всей группы (у него лимит — 10 рассылок каждого вида).

Тестовая база и аккаунты те же, что для старосты (`export ISHKA_DB=~/ishka-test.sqlite` в каждом окне, аккаунты из шага 1).
Часть Б проверяет модель, обученную **после 12 октября**: прежние модели инструментов удаления не знают.

## Часть А. Без модели (удаление)

```bash
PYTHONPATH=. python3 - <<'EOF'
import datetime as dt
from store import Store
from backend import Backend
st = Store()
def be(login):
    acc = st.account(login=login)
    return Backend(dt.datetime(2026, 10, 12, 8, 0), st.profile(acc), st, acc["id"])
def say(who, text, tool, args):  # новое сообщение в чате и вызов, который сделала бы модель
    who.new_turn()
    print(f"«{text}» →", who.call(tool, args))
s = be("ivanov")
for t in ["Купить флешку", "Код от шкафчика 4512", "Пароль от вайфая в КЦ", "Вернуть книгу в НТБ"]:
    s.call("add_note", {"text": t})
say(s, "мои заметки", "list_notes", {"kind": "note"})
say(s, "удали 2", "delete_items", {"kind": "note", "numbers": [2]})
say(s, "и 4 тоже", "delete_items", {"kind": "note", "numbers": [4]})
say(s, "удали заметку про флешку", "delete_items", {"kind": "note", "query": "флешку"})
say(s, "удали все заметки", "delete_items", {"kind": "note", "all": True})
say(s, "да", "delete_items", {"kind": "note", "all": True})
for i in range(10):
    s.call("add_note", {"text": f"Заметка {i + 1}"})
say(s, "запиши: купить тетрадь", "add_note", {"text": "Купить тетрадь"})
say(s, "3", "delete_items", {"kind": "note", "numbers": [3]})
print("и записал новую:", s.call("add_note", {"text": "Купить тетрадь"}))
h, s1 = be("petrova"), be("sidorov")
say(h, "напомни группе завтра в 18:00 про собрание", "group_create_reminder", {"text": "Собрание группы", "at": "tomorrow 18:00"})
say(s1, "убери напоминание про собрание", "delete_items", {"kind": "reminder", "query": "собрание"})
print("у ivanov собрание есть:", any(r["text"] == "Собрание группы" for r in be("ivanov").list_notes()["reminders"]))
say(h, "отмени рассылку про собрание", "group_delete_post", {"query": "собрание"})
print("у ivanov собрание есть:", any(r["text"] == "Собрание группы" for r in be("ivanov").list_notes()["reminders"]))
EOF
```

| Строка вывода | Что значит |
|---|---|
| `«мои заметки» → {'notes': [{'n': 1, 'text': 'Купить флешку'}, ...]` | заметки с номерами 1–4 |
| `«удали 2» → {'ok': True, 'deleted': [{'text': 'Код от шкафчика 4512'}], 'left': 3}` | удалена вторая |
| `«и 4 тоже» → ... 'Вернуть книгу в НТБ' ...` | четвёртая из того же списка: номера не сдвинулись |
| `«удали заметку про флешку» → ... 'Купить флешку' ...` | нашлась по слову |
| `«удали все заметки» → {'confirm': True, 'count': 1, ...}` | сначала только вопрос, ничего не удалено |
| `«да» → {'ok': True, ... 'left': 0}` | удалено после «да» |
| `«запиши: купить тетрадь» → {'error': 'limit', 'limit': 10, 'items': [...]}` | 11-я заметка не влезла, список из 10 с номерами |
| `«3» → ... 'Заметка 3' ...`, затем `и записал новую: {'ok': True, ...}` | удалил третью и записал новую |
| `«напомни группе ...» → {'ok': True, 'fire_at': '2026-10-13 18:00', 'recipients': 2}` | староста разослал напоминание двоим |
| `«убери напоминание про собрание» → {'ok': True, 'hidden': [...]}` | у `sidorov` оно скрыто (`hidden`, а не `deleted`) |
| `у ivanov собрание есть: True` | у остальных рассылка осталась |
| `«отмени рассылку про собрание» → {'ok': True, 'deleted': [...]}`, затем `у ivanov собрание есть: False` | староста отменил рассылку для всех |

Повторный запуск: удали тестовую базу и заведи аккаунты заново (последний шаг и шаг 1), иначе заметки и рассылки задвоятся.

## Часть Б. С моделью (удаление)

Сначала староста: `python chat.py --login petrova --now "2026-10-12 08:00"` (пароль `starosta1`), напиши
`напомни группе завтра в 18:00 про собрание` (появится `[group_create_reminder ...]`) и выйди (Ctrl+D).

После части А у `ivanov` ровно 10 заметок. Войди: `python chat.py --login ivanov --now "2026-10-12 08:00"` (пароль `student1`) и пиши по очереди:

| Что написать | Что должно появиться |
|---|---|
| `запиши в заметки: купить зарядку` | `[add_note ...]`, затем «уже 10 заметок — это максимум» и список с номерами 1–10 |
| `5` | `[delete_items {"kind": "note", "numbers": [5]}]`, затем снова `[add_note ...]`: удалил пятую и записал новую |
| `мои заметки` | список с номерами, «Купить зарядку» в нём есть |
| `удали 2` | `[delete_items {"kind": "note", "numbers": [2]}]`, ответ «Удалил …» |
| `и 3 тоже` | `numbers: [3]`: удалена третья из того же списка |
| `удали заметку про тетрадь` | `[delete_items {"kind": "note", "query": ...}]` |
| `удали все заметки` | вопрос «удалить все …?»; удаления ещё нет |
| `да` | `[delete_items {"kind": "note", "all": true}]`, «Удалил все …» |
| `отмени для всех напоминание про собрание` | «отменить для всей группы может только староста», Ишка предлагает убрать его у тебя |
| `да` | `[delete_items {"kind": "reminder", "query": ...}]`: напоминание скрыто только у тебя |

Снова староста (`--login petrova`): `отмени рассылку` — Ишка покажет разосланное и спросит, отменить ли; `да` — строка
`[group_delete_post ...]` и ответ, что напоминание пропало у всей группы.

## Последний шаг. Убрать за собой

Выйди из чатов и удали тестовую базу вместе со всеми тестовыми аккаунтами и рассылками. Настоящая база `db/ishka.sqlite` не тронута:

```bash
rm ~/ishka-test.sqlite
unset ISHKA_DB
```

`unset` нужно, чтобы следующие запуски в этом окне снова работали с настоящей базой.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `Базы аккаунтов ... нет` | в этом окне не выполнен `export ISHKA_DB=~/ishka-test.sqlite` или не заведены аккаунты (шаг 1) |
| `Неверный логин или пароль` | пароли из шага 1: `starosta1`, `student1`, `student2`. Логины без учёта регистра |
