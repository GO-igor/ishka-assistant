# Быстрый запуск Ишки на Mac (всё уже установлено)

Эта памятка для тех, у кого уже стоят Homebrew и llama.cpp, лежит папка `~/ishka-model` с моделью и склонирован проект `~/ishka-assistant`.
Если что-то из этого нет, начни с [RUN_MAC.md](RUN_MAC.md): там установка с нуля.

Нужны два окна Терминала (Cmd+N открывает новое).

---

## Окно 1. Сервер с моделью

```bash
cd ~/ishka-model
llama-server -m ishka-Q4_K_M.gguf --jinja -c 16384 --port 8080
```

Подставь своё имя файла, если оно другое (`ls ~/ishka-model`). Готово, когда появилась строка `server is listening on http://127.0.0.1:8080`.
**Окно не закрывай**: пока оно открыто, модель работает. Остановить: Ctrl+C.

## Окно 2. Чат

Если я писал, что обновил проект, сначала скачай обновления:

```bash
cd ~/ishka-assistant
git pull
```

Потом запусти чат:

```bash
cd ~/ishka-assistant
source .venv/bin/activate
python chat.py --login ivanov
```

Подставь свой логин, пароль чат спросит (символы не видны). Без входа Ишка не работает: подгруппа, преподаватель английского и курсы (А)
берутся из аккаунта. Если аккаунта ещё нет, заведи его один раз (поменять потом: `python accounts.py edit ivanov --subgroup 1 --english Пичугова`):

```bash
python accounts.py add ivanov --group 8К51 --subgroup 2 --english Аксёнова --name "Иван Иванов"
```

Появится `ты>`: пиши вопрос и жми Enter. Выход: Ctrl+D. Остановить длинный ответ: Ctrl+C.
Сработавшие напоминания Ишка пишет сам при входе и перед каждым ответом (`⏰ Напоминаю: …`), утренний брифинг показывает сам при первом входе за день с 7:30 до 12:00.
Пока чат открыт, он раз в минуту сам проверяет напоминания и брифинг, даже если ты ничего не пишешь; если сервер модели не ответил, брифинг повторится позже.

Полезные флаги: `--now "2026-10-12 09:50"` подменяет время (прошедшее тогда из базы не удаляется), `--debug` показывает вызовы инструментов и вероятность вызова.
Чтобы при проверках не вводить пароль каждый раз: `ISHKA_PASSWORD=student1 python chat.py --login ivanov`.

## Если не заработало

| Симптом | Что делать |
|---|---|
| `[сервер ... не отвечает ...]` | окно 1 закрыто или сервер ещё грузится: подожди `server is listening` |
| `command not found: python` | в этом окне не активировано окружение: `cd ~/ishka-assistant && source .venv/bin/activate` |
| `command not found: llama-server` | llama.cpp не установлен: шаг 2 из RUN_MAC.md |
| `failed to open ... .gguf` | неверное имя файла или папка: `ls ~/ishka-model` |
| `address already in use` | сервер уже запущен в другом окне, или возьми другой порт: `--port 8081` и `python chat.py --url http://localhost:8081 ...` |
| `Базы аккаунтов ... нет` | аккаунт ещё не заведён: `python accounts.py add ...` (см. выше) |
| `Не читается список запретных фраз` | в `db/blocklist.json` ошибка (чаще всего забыта запятая или кавычка): исправь файл, чат покажет место |
| Ишка отвечает странно | `python diag_server.py --subgroup 2 --english "Аксёнова Н. В."` и пришли весь вывод; подробнее в шаге 7 RUN_MAC.md |

# Как проверить «Умного старосту»

Староста отправляет группе (или подгруппе) объявления и Д/З, студенты видят их в утреннем брифинге и в списке своих записей отдельным блоком «📢 От старосты».
Удаляет их только староста, сразу у всей группы. Сами они пропадают: объявление — после своего события (без даты — через неделю), Д/З — после срока сдачи.
Проверка занимает минут десять. У неё две части:
- **Часть А** не требует модели: проверяется сама логика (кто что получает). Сервер из окна 1 для неё не нужен.
- **Часть Б** проверяет всё вместе с моделью, как будет в жизни. Модель должна быть обучена на датасете **от 14 октября** или новее, иначе она не знает
  инструментов старосты `group_announce`, `group_add_homework`, `group_delete_post` (прежняя модель зовёт инструменты, которых больше нет: нужно переобучение, GUIDE.md, шаг 2).

Чтобы не мусорить в настоящей базе, всё делается в отдельной тестовой базе. Эту строку нужно выполнить **в каждом окне**, где идёт проверка:

```bash
cd ~/ishka-assistant
source .venv/bin/activate
export ISHKA_DB=~/ishka-test.sqlite
```

## Шаг 1. Завести тестовые аккаунты

Один староста и два студента в одной группе, но в разных подгруппах (подгруппы нужны, чтобы проверить объявление только части группы):

```bash
python accounts.py add petrova --group 8К51 --role starosta --name "Анна Петрова" --password starosta1
python accounts.py add ivanov --group 8К51 --subgroup 2 --english Аксёнова --name "Иван Иванов" --password student1
python accounts.py add sidorov --group 8К51 --subgroup 1 --name "Пётр Сидоров" --password student2
python accounts.py list
```

Ожидается список из трёх строк: староста `petrova`, студент `ivanov` (подгруппа 2), студент `sidorov` (подгруппа 1).
Для проверки пароли простые. Для настоящих аккаунтов пароль не пишут в команде: убери `--password`, и он спросится скрыто.

## Часть А. Без модели

Скрипт делает то же, что сделала бы модель, когда староста пишет в чат, но вызывает бэкенд напрямую. Время в нём зафиксировано на понедельник, 12 октября 2026, 08:00.

```bash
PYTHONPATH=. python3 - <<'EOF'
import datetime as dt
from store import Store
from backend import Backend
st = Store()
def be(login):
    acc = st.account(login=login)
    return Backend(dt.datetime(2026, 10, 12, 8, 0), st.profile(acc), st, acc["id"])
head, s2, s1 = be("petrova"), be("ivanov"), be("sidorov")
print(head.group_add_homework("матлог", "№5–10", due="friday"))
print(head.group_announce("Хакатон, МКЦ", at="saturday 10:00"))
print(head.group_announce("Взять зачётки", at="tomorrow 09:00", subgroup=2))
print(head.group_announce("Пройти опрос о качестве обучения"))
print("студент пытается отправить:", s2.group_announce("Собрание группы"))
print("БРИФИНГ ivanov (подгруппа 2):", s2.get_daily_brief().get("from_starosta"))
print("БРИФИНГ sidorov (подгруппа 1):", s1.get_daily_brief().get("from_starosta"))
EOF
```

Что должно получиться (порядок строк именно такой):

| Строка вывода | Что значит |
|---|---|
| `{'ok': True, 'subject': 'Математическая логика и теория алгоритмов', 'due': '2026-10-16', 'no_class_that_day': True, 'recipients': 2}` | Д/З ушло двум студентам группы. Название предмета бэкенд узнал сам, срок «пятница» превратил в 16 октября (пары по матлогике в этот день нет, поэтому срок — просто день) |
| `{'ok': True, 'text': 'Хакатон, МКЦ', 'at': '2026-10-17 10:00', 'until': '2026-10-17 10:00', 'recipients': 2}` | объявление ушло обоим; `until` — когда оно удалится само (после события) |
| `{'ok': True, 'text': 'Взять зачётки', 'at': '2026-10-13 09:00', 'until': '2026-10-13 09:00', 'recipients': 1, 'subgroup': 2}` | объявление ушло **одному** человеку: только второй подгруппе |
| `{'ok': True, 'text': 'Пройти опрос о качестве обучения', 'until': '2026-10-19 08:00', 'recipients': 2}` | объявление без даты: продержится неделю |
| `студент пытается отправить: {'error': 'not_starosta'}` | обычному студенту отправлять группе запрещено |
| `БРИФИНГ ivanov ...` | **четыре** пункта: опрос, зачётки, Д/З, хакатон |
| `БРИФИНГ sidorov ...` | **три** пункта: опрос, Д/З и хакатон, объявления для второй подгруппы у него нет |

Если все семь строк такие, логика старосты работает. Результат повторяется: перед повторным запуском удали тестовую базу (последний шаг) и заведи аккаунты заново, иначе объявления задвоятся.

## Часть Б. С моделью

Окно 1: запусти сервер (см. начало памятки). Окно 2: выполни три строки подготовки выше (`cd`, `source`, `export`).
Если часть А уже сделана, сначала удали тестовую базу (`rm ~/ishka-test.sqlite`) и заведи аккаунты заново (шаг 1):
иначе объявления задвоятся, и числа ниже не совпадут.

### Б1. Староста отправляет

Войди как староста. Время зафиксировано, чтобы «пятница» и «завтра» означали одно и то же при каждой проверке:

```bash
python chat.py --login petrova --now "2026-10-12 08:00"
```

Спросит пароль (`starosta1`, символы не видны). Ишка поздоровается: «Привет, Анна Петрова! Группа 8К51, ты староста: можешь отправлять группе объявления и Д/З.»
Если написано просто «Группа 8К51.» без слов «ты староста», у аккаунта роль студента: `python accounts.py edit petrova --role starosta`.
Сразу после приветствия Ишка сам покажет утренний брифинг (`[get_daily_brief {"day": "today"}]`): 08:00 попадает в 7:30–12:00, а с `--now` день брифинга не запоминается.

Пиши по очереди:

| Что написать | Что должно появиться |
|---|---|
| `выдай группе дз по матлогу к пятнице: №5–10` | строка `[group_add_homework {...}]` с предметом, заданием и сроком `friday`, потом ответ вроде «Отправил группе: срок пт 16 октября» |
| `объяви всем — хакатон, МКЦ, в субботу в 10:00` | `[group_announce {...}]` с текстом про хакатон и `at: "saturday 10:00"`, потом подтверждение |
| `напомни второй подгруппе завтра в 9:00: взять зачётки` | `[group_announce {...}]` с `at: "tomorrow 09:00"` и `subgroup: 2`, потом подтверждение, что дойдёт второй подгруппе |
| `объяви группе: пройти опрос о качестве обучения` | `[group_announce {...}]` без `at`, в ответе «через неделю оно удалится само» |

Слова ответа у модели могут чуть отличаться, важно другое: вызов нужного `group_...` в квадратных скобках, правильные аргументы и в ответе число получателей (2, а для второй подгруппы 1).
Если вместо вызова Ишка просто отвечает текстом «отправил», а строки `[group_...]` нет (или в ней `group_add_event`, `group_create_reminder`), модель обучена до 14 октября. Тогда проверяй часть А и см. «Если что-то не так» ниже.

Выйди: Ctrl+D.

### Б2. Студент второй подгруппы видит объявления

```bash
python chat.py --login ivanov --now "2026-10-12 08:00"
```

Пароль `student1`. Брифинг Ишка покажет сам, сразу после входа. Дальше напиши по очереди:

| Что написать | Что должно появиться |
|---|---|
| (ничего, брифинг сразу после входа) | `[get_daily_brief {"day": "today"}]`, пары на понедельник и ниже блок **«📢 От старосты»** с четырьмя пунктами: опрос, зачётки завтра в 09:00, Д/З по матлогике №5–10 к пт 16 октября, хакатон в сб 17 октября в 10:00 в МКЦ |
| `мои заметки` | `[list_notes {}]`: своих записей пока нет, а блок «📢 От старосты» тот же (без номеров: это не твои записи) |
| `удали объявление про хакатон` | без вызова инструмента: удалить объявление может только староста, а пропадёт оно само после события |

Выйди: Ctrl+D.

### Б3. Студент первой подгруппы не видит чужого

```bash
python chat.py --login sidorov --now "2026-10-12 08:00"
```

Пароль `student2`. В брифинге (он появится сам) в блоке «📢 От старосты» должно быть **три** пункта (опрос, Д/З и хакатон), без зачёток: это объявление было только для второй подгруппы. Проверь и `мои заметки`: зачёток там быть не должно.

### Б4. Студент не может отправлять группе

Всё ещё под `sidorov` напиши `объяви группе: собрание в пятницу в 18:00`. Строки `[group_announce ...]` быть не должно: у студента инструментов старосты в промпте нет. Ишка ответит текстом (что-то вроде «отправлять группе может только староста») и предложит записать это тебе.
Если модель всё-таки вызвала инструмент, бэкенд его отклонит ответом `not_starosta`, и в базу ничего не попадёт.

### Б5. Когда срок прошёл

Проверка, что прошедшее уходит само. Войди студентом второй подгруппы, но уже во вторник, после времени объявления про зачётки:

```bash
python chat.py --login ivanov --now "2026-10-13 09:30"
```

В брифинге (он снова появится сам) объявления про зачётки уже нет (его время, 9:00 вторника, прошло), а опрос, Д/З и хакатон на месте. Теперь войди с `--now "2026-10-18 08:00"`:
от старосты остался только опрос — у него нет даты, и он живёт неделю (до 19 октября 08:00), а срок Д/З (пятница) и хакатон (суббота) уже прошли.
С `--now "2026-10-20 08:00"` блока «📢 От старосты» нет совсем.
Без `--now` чат при входе ещё и удаляет прошедшие объявления и Д/З из базы, у всех сразу это делает `python accounts.py cleanup` (он для сайта: удаляет и напоминания, которые чат ещё не показал).

# Как проверить удаление и лимиты

Свои заметки и напоминания Ишка показывает одним списком с номерами: сначала напоминания по времени (и напоминания о Д/З), потом заметки.
Удалить можно по номеру («удали 2»), по словам («удали напоминание про деканат») или все сразу: тогда Ишка сначала переспросит, а удалит после «да».
Номера берутся из последнего показанного списка и после удаления не сдвигаются: «и 4 тоже» — та же четвёртая.
Лимит — 10 заметок и напоминаний вместе и отдельно 10 напоминаний о Д/З: на лишнюю Ишка покажет список и предложит удалить старую.
Объявления и Д/З старосты студент удалить не может (они пропадут сами), а староста удаляет их сразу у всей группы (у него лимит — 10 действующих объявлений и 10 Д/З).

Тестовая база и аккаунты те же, что для старосты (`export ISHKA_DB=~/ishka-test.sqlite` в каждом окне, аккаунты из шага 1).
Часть Б проверяет модель, обученную на датасете **от 14 октября**: прежние модели этих инструментов не знают.

## Часть А. Без модели (удаление)

```bash
PYTHONPATH=. python3 - <<'EOF'
import datetime as dt
from store import Store
from backend import Backend
st = Store()
def be(login):
    acc = st.account(login=login)
    return Backend(dt.datetime(2026, 10, 12, 8, 0), st.profile(acc), st, acc["id"])
def say(who, text, tool, args):  # новое сообщение в чате и вызов, который сделала бы модель
    who.conv.new_turn()
    print(f"«{text}» →", who.call(tool, args))
s = be("ivanov")
for t in ["Купить флешку", "Код от шкафчика 4512", "Пароль от вайфая в КЦ", "Вернуть книгу в НТБ"]:
    s.call("add_note", {"text": t})
say(s, "напомни завтра в 9:00 позвонить в деканат", "add_note", {"text": "Позвонить в деканат", "at": "tomorrow 09:00"})
say(s, "сделай напоминание о дз по матлогу: №5–10", "add_homework_reminder", {"subject": "матлог", "task": "№5–10"})
say(s, "мои заметки", "list_notes", {})
say(s, "удали 4", "delete_items", {"numbers": [4]})
say(s, "и 6 тоже", "delete_items", {"numbers": [6]})
say(s, "удали напоминание про деканат", "delete_items", {"query": "деканат"})
say(s, "удали все", "delete_items", {"all": True})
say(s, "да", "delete_items", {"all": True})
for i in range(10):
    s.call("add_note", {"text": f"Заметка {i + 1}"})
say(s, "просто запиши", "add_note", {"text": "Купить тетрадь"})  # перед этим «запиши: купить тетрадь» и вопрос «напомнить?»
say(s, "3", "delete_items", {"numbers": [3]})
print("и записал новую:", s.call("add_note", {"text": "Купить тетрадь"}))
h, s1 = be("petrova"), be("sidorov")
say(h, "объяви группе: собрание в среду в 18:00", "group_announce", {"text": "Собрание группы", "at": "wednesday 18:00"})
print("у sidorov собрание есть:", any(p.get("text") == "Собрание группы" for p in s1.list_notes().get("from_starosta", [])))
print("студент пытается удалить:", s1.call("group_delete_post", {"query": "собрание"}))
say(h, "отмени объявление про собрание", "group_delete_post", {"kind": "announcement", "query": "собрание"})
print("у sidorov собрание есть:", any(p.get("text") == "Собрание группы" for p in s1.list_notes().get("from_starosta", [])))
EOF
```

| Строка вывода | Что значит |
|---|---|
| `«напомни завтра в 9:00 позвонить в деканат» → {'ok': True, 'fire_at': '2026-10-13 09:00'}` | со временем `add_note` ставит напоминание |
| `«сделай напоминание о дз по матлогу: №5–10» → {'ok': True, ..., 'class_at': '2026-10-15 14:35', 'fire_at': '2026-10-14 19:00'}` | бэкенд нашёл ближайшую пару по матлогике (чт 15 октября, 14:35) и поставил напоминание накануне в 19:00 |
| `«мои заметки» → {'items': [{'n': 1, 'text': 'Позвонить в деканат', ...}, {'n': 2, 'text': '№5–10', ...}, {'n': 3, 'text': 'Купить флешку'}, ...], 'from_starosta': [...]}` | один список с номерами 1–6: сначала напоминания по времени, потом заметки; ниже объявления и Д/З старосты из проверки старосты, без номеров |
| `«удали 4» → {'ok': True, 'deleted': [{'text': 'Код от шкафчика 4512'}], 'left': 5}` | удалена четвёртая |
| `«и 6 тоже» → ... 'Вернуть книгу в НТБ' ...` | шестая из того же списка: номера не сдвинулись |
| `«удали напоминание про деканат» → ... 'Позвонить в деканат' ...` | нашлось по слову |
| `«удали все» → {'confirm': True, 'count': 3, ...}` | сначала только вопрос, ничего не удалено |
| `«да» → {'ok': True, ... 'left': 0}` | удалено после «да»: и заметки, и напоминание о Д/З |
| `«просто запиши» → {'error': 'limit', 'limit': 10, 'items': [...]}` | 11-я запись не влезла, список из 10 с номерами |
| `«3» → ... 'Заметка 3' ...`, затем `и записал новую: {'ok': True}` | удалил третью и записал новую |
| `«объяви группе: собрание в среду в 18:00» → {'ok': True, 'text': 'Собрание группы', 'at': '2026-10-14 18:00', 'until': '2026-10-14 18:00', 'recipients': 2}` | староста отправил объявление двоим |
| `у sidorov собрание есть: True` | студент его видит |
| `студент пытается удалить: {'error': 'not_starosta'}` | удалить объявление у группы студент не может |
| `«отмени объявление про собрание» → {'ok': True, 'deleted': [...], 'left': 3}`, затем `у sidorov собрание есть: False` | староста удалил его у всей группы (`left` — сколько у группы осталось объявлений: три из проверки старосты) |

Повторный запуск: удали тестовую базу и заведи аккаунты заново (последний шаг и шаг 1), иначе заметки и объявления задвоятся.

## Часть Б. С моделью (удаление)

Сначала староста: `python chat.py --login petrova --now "2026-10-12 08:00"` (пароль `starosta1`), напиши
`объяви группе: собрание в среду в 18:00` (появится `[group_announce ...]` с `at: "wednesday 18:00"`) и выйди (Ctrl+D).

После части А у `ivanov` ровно 10 записей. Войди: `python chat.py --login ivanov --now "2026-10-12 08:00"` (пароль `student1`). Ишка сам покажет брифинг, потом пиши по очереди:

| Что написать | Что должно появиться |
|---|---|
| `запиши в заметки: купить зарядку` | без вызова: Ишка переспрашивает, напомнить ли («скажи время или „просто запиши“») |
| `просто запиши` | `[add_note {"text": "Купить зарядку"}]`, затем «уже 10 заметок и напоминаний — это максимум» и список с номерами 1–10 |
| `5` | `[delete_items {"numbers": [5]}]`, затем снова `[add_note ...]`: удалил пятую и записал новую |
| `мои заметки` | `[list_notes {}]`: список с номерами, «Купить зарядку» в нём есть; ниже блок «📢 От старосты» с собранием |
| `удали 2` | `[delete_items {"numbers": [2]}]`, ответ «Удалил …» |
| `и 3 тоже` | `numbers: [3]`: удалена третья из того же списка |
| `удали все` | `[delete_items {"all": true}]`, но в ответе только вопрос «удалить все …?»: ничего ещё не удалено |
| `да` | снова `[delete_items {"all": true}]`, «Удалил все …» |
| `напомни завтра в 9:00 позвонить в деканат` | `[add_note {"text": "Позвонить в деканат", "at": "tomorrow 09:00"}]`, ответ «завтра в 09:00 напомню» |
| `сделай напоминание о дз по матлогу: №5–10` | `[add_homework_reminder {"subject": "матлог", "task": "№5–10"}]`: напомнит в ср 14 октября в 19:00, накануне пары в чт 15 октября в 14:35 |
| `мои напоминания` | `[list_notes {"kind": "reminder"}]`: 1. завтра в 09:00 — Позвонить в деканат; 2. в ср 14 октября в 19:00 — Д/З по матлогике |
| `удали напоминание про деканат` | `[delete_items {"query": "деканат"}]`, ответ «Удалил напоминание …» |
| `удали объявление про собрание` | без вызова: удалить его может только староста, а пропадёт оно само после собрания |

Выйди (Ctrl+D) и войди снова, уже в момент напоминания: `python chat.py --login ivanov --now "2026-10-14 19:00"`. Сразу после приветствия будет строка
`⏰ Напоминаю: Д/З к паре «Математическая логика и теория алгоритмов» (15.10 в 14:35): №5–10`. Без `--now` сработавшее напоминание после этого
удаляется из базы, с `--now` база не меняется, и проверку можно повторить.

Снова староста: `python chat.py --login petrova --now "2026-10-12 08:00"` (пароль `starosta1`; до собрания, иначе оно уже удалено), `отмени объявление про собрание` — строка `[group_delete_post {"kind": "announcement", "query": ...}]` и ответ,
что объявление пропало у всей группы. Или `удали что-нибудь из отправленного группе` — Ишка покажет объявления и Д/З группы с номерами, а на номер удалит выбранное у всех.

## Последний шаг. Убрать за собой

Выйди из чатов и удали тестовую базу вместе со всеми тестовыми аккаунтами, заметками и объявлениями. Настоящая база `db/ishka.sqlite` не тронута:

```bash
rm ~/ishka-test.sqlite
unset ISHKA_DB
```

`unset` нужно, чтобы следующие запуски в этом окне снова работали с настоящей базой.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `Базы аккаунтов ... нет` | в этом окне не выполнен `export ISHKA_DB=~/ishka-test.sqlite` или не заведены аккаунты (шаг 1) |
| `Неверный логин или пароль` | пароли из шага 1: `starosta1`, `student1`, `student2`. Логины без учёта регистра |
| Староста пишет, а Ишка «только староста» | роль студента: `python accounts.py edit petrova --role starosta` и войти заново |
| Вместо `[group_...]` просто текст «отправил» или вызов `group_add_event`, `group_create_reminder` | модель обучена до 14 октября и новых инструментов не знает: нужно переобучение на обновлённом датасете (GUIDE.md, шаг 2), пока проверяй часть А |
| Студент не видит объявление | это аккаунты в разных группах (`python accounts.py list`), объявление для другой подгруппы или время `--now` уже после события |
| Брифинг не появился сам | время `--now` вне 7:30–12:00 или брифинг сегодня уже был (без `--now` день запоминается в аккаунте): напиши `брифинг` |
| Отправилось дважды | проверку запускали повторно в той же базе: удали `~/ishka-test.sqlite` и начни с шага 1 |
| Ишка вызывает инструмент не с теми аргументами | запиши фразу и пришли: из неё получится пример для следующего обучения |
| На «запиши …» Ишка сначала спрашивает, напомнить ли | так и задумано: назовёшь время — будет напоминание, «просто запиши» — заметка |
| «удали 2» удаляет не ту запись | номер берётся из последнего списка, который показал Ишка. Попроси список заново («мои заметки») и назови номер из него |
| «удали все» сразу ничего не удаляет | так и задумано: Ишка сначала переспрашивает и удаляет после «да» следующим сообщением |
| Вместо `[delete_items ...]` просто текст «удалил» | модель обучена до 14 октября и новых инструментов не знает: нужно переобучение (GUIDE.md, шаг 2), пока проверяй часть А удаления |
