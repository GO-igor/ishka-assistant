# Инструкция по разметке датасета

## Формат
Одна строка `data/*.jsonl` = один диалог: `{"messages": [...]}`. Порядок ролей:
`system` → `user` → (`assistant` с `tool_calls` → `tool`)* → `assistant` (текст).
Образец формата: `data/sample.jsonl` (данные выдуманы, в обучение не идёт). Схема инструментов: `tools.json`.
Настоящий датасет собирает `gen_dataset.py` из базы `db/` через `backend.py`: ответы инструментов в нём реальные.

- **system**: шаблон из `build_samples.py`, но *меняй* дату, время, день недели и группу. У старосты профиль кончается на
  «; староста группы.» — только в таких диалогах в промпте есть инструменты `group_*`.
- **tool_calls**: только инструменты из `tools.json`, только описанные аргументы.
- **tool**: JSON-ответ бэкенда — бери его из `backend.py`, а не пиши руками.
- **финальный ответ**: опирается *только* на данные из `tool`.

## Правила стиля
- На «ты», 1–5 строк, списки для пар и маршрутов, 0–2 эмодзи.
- Время — 08:30, дни — «пн/вт» или «завтра (чт)».
- Без канцелярита («Ваш запрос обработан» — нельзя).
- Нет данных → честно сказать и предложить, что можно сделать. Никаких выдуманных аудиторий и ФИО.
- Не хватает параметра (когда напомнить? какая аудитория?) → один короткий уточняющий вопрос.
- Удаление: номер — только из списка, который Ишка показал раньше; «удали все» — сначала вопрос, удаление после «да».
- Объявления и Д/З старосты студент не удаляет: Ишка отвечает текстом, что их удаляет только староста, а пропадут они сами.

## Пропорции (как в текущем датасете, ~2000 диалогов)
| Категория | Доля |
|---|---|
| Расписание (сегодня/завтра/день недели/«какая следующая пара») | 16% |
| Аудитории, маршруты, «успеваю ли я» | 16% |
| Где перекусить | 7% |
| Преподаватели | 7% |
| Заметки и напоминания (`add_note`; около половины — после вопроса «когда напомнить?») | 9% |
| Напоминание о Д/З (`add_homework_reminder`) | 4% |
| Брифинг (вход `[авто] утренний брифинг` и по просьбе) | 5% |
| Сессия и мероприятия | 6% |
| Староста: объявления, Д/З группе и их удаление | 6% |
| Удаление и лимиты: список с номерами, «удали 2», «удали все» → «да», «уже 10 записей» | 11% |
| Без инструментов: болтовня, вне темы, отказ выдумывать, вежливый отказ от того, чего Ишка не делает | 13% |

Уточняющие вопросы, ошибки инструментов и пустые результаты — внутри своих категорий.

Заметка и напоминание — один инструмент `add_note`: со временем (`in_minutes`/`in_hours`/`in_days` или `at`) это напоминание,
без времени — заметка. Время не названо → Ишка сначала спрашивает («Напомнить об этом? Скажи время или „просто запиши“»):
«напомни завтра в 9 позвонить в деканат» → `add_note` с `at: "tomorrow 09:00"`, «запиши: купить флешку» → вопрос, затем на
«просто запиши» → `add_note` только с `text`. Напоминание о Д/З — отдельный инструмент: «сделай напоминание о дз по матлогу: №5–10»
→ `add_homework_reminder` (бэкенд сам ставит его накануне ближайшей пары в 19:00). Предмет не назван («сделай напоминание о ДЗ»)
→ Ишка спрашивает «По какому предмету?», и только после ответа вызывает инструмент.
Староста: «объяви группе: собрание в среду в 18:00» → `group_announce` (`at: "wednesday 18:00"`, без даты — без `at`),
«выдай группе дз по матлогу к пятнице: №5–10» → `group_add_homework` (`due: "friday"`, по умолчанию `next_class`),
«отмени объявление про собрание» → `group_delete_post`. Студенту на «объяви группе …» Ишка отвечает текстом, что это может только староста.
На то, чего Ишка больше не делает («объясни тему», план повторения, дедлайны, свой список Д/З, ввод экзаменов), — вежливый отказ
текстом и предложение того, что он умеет («Объяснять темы я не умею 🙂 … могу подсказать, когда у тебя ближайшая пара»).

## Разнообразие формулировок
Пиши как пишут студенты: «чё по парам», «где ауд 412», «кто ведет прогу»,
«матан/дискретка/физра», опечатки, без знаков препинания, голосовые расшифровки.
Одно намерение — минимум 10 разных формулировок.

## Как генерировать быстрее
1. Шаблоны фраз в `gen_dataset.py` (функция на каждую категорию) × реальные данные из базы.
2. Большой LLM перефразирует часть ответов (`data/paraphrases.json`), `paraphrase.py` проверяет, что факты не поменялись.
3. Человек выборочно проверяет диалоги (особенно аргументы и отсутствие выдумок).
4. `python validate_dataset.py data/train.jsonl` — должно быть «Ошибок: 0».
5. Eval-набор (`data/eval.jsonl`) не пересекается с train по формулировкам: последние 2 фразы каждого списка
   в `gen_dataset.py` идут только в eval. Новые категории в eval — поровну, по 5 примеров.
