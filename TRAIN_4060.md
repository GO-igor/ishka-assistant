# Обучение Ишки на своей видеокарте RTX 4060 (8 ГБ)

Коротко: Windows + WSL2 (Ubuntu внутри Windows), одна команда `./train_4060.sh`, примерно 25–35 часов вместе с оценкой
и экспортом. На выходе — `.gguf` лучшей модели для Mac, как раньше из Colab. Обучение в Colab по [GUIDE.md](GUIDE.md)
тоже продолжает работать, его чекпоинты этот режим не трогает.

## Программа обучения

| | Colab (T4, как было) | RTX 4060 (этот режим) |
|---|---|---|
| Эпох (сколько раз модель видит каждый пример) | 1 | **3** |
| Модель | одна, после обучения | **после каждой эпохи** (`out/epoch-1`, `-2`, `-3`) |
| Какая идёт в `.gguf` | единственная | **лучшая** по тем же 5 проверкам `evaluate.py`, что в Colab |
| Ранг LoRA (сколько «места» у адаптера) | 16 | 32 |
| Шаг обучения (lr) | 2e-4 | 1e-4: примеры повторяются трижды, учим аккуратнее |
| Оптимизатор | обычный | 8-битный: на ~0.4 ГБ меньше памяти видеокарты |
| Длина примера, batch | 4096 токенов, 1 × накопление 16 | то же (самый длинный пример — 4039 токенов) |
| Чекпоинт | каждые 10 шагов | каждые 20 шагов (~30–60 мин) и в конце каждой эпохи |

Почему так. В Colab успевали только одну эпоху. Больше эпох — модель лучше запоминает редкие случаи
(аргументы, цепочки, уточнения), но после какой-то эпохи начинает заучивать сам датасет и хуже понимает живые фразы.
Поэтому сохраняется модель после каждой эпохи, и `compare_epochs.py` выбирает лучшую по цифрам, а не «последнюю».

Базовая модель та же, Qwen3-4B. Qwen3-8B в 8 ГБ с примерами до 4096 токенов не помещается, и на Mac она была бы
вдвое медленнее. Датасет тот же: переобучать после изменений датасета нужно так же, как раньше.

### Сколько времени

| Что | Примерно | Точно |
|---|---|---|
| Одна эпоха (203 шага по 16 примеров) | 6–10 ч (в Colab на T4 было ~13 ч) | покажет замер, шаг 6 |
| 3 эпохи | 18–30 ч | |
| Оценка каждой модели (5 проверок) | ~1–1.5 ч, всего 3–4.5 ч | `compare_epochs.py` пишет время каждой проверки |
| Экспорт в `.gguf` | ~30 мин | |
| **Всего** | **~22–35 ч** из лимита 60 ч | |

Замер (шаг 6) показывает прогноз для 1–4 эпох. Если 3 эпохи с оценкой выходят больше 50 ч (запас на перезапуски),
он сам посоветует `EPOCHS=2`.

## Шаг 1. WSL2 и Ubuntu (один раз)

1. Обнови драйвер NVIDIA в Windows (GeForce Experience / NVIDIA App или nvidia.com/drivers). Драйвер для Linux ставить
   **не нужно**: Ubuntu внутри Windows пользуется виндовым.
2. Пуск → набери `PowerShell` → *Запуск от имени администратора*:
   ```powershell
   wsl --install -d Ubuntu-24.04
   ```
   Перезагрузи компьютер. После перезагрузки откроется окно Ubuntu: придумай имя пользователя и пароль (латиницей;
   пароль при вводе не отображается, это нормально).
3. Дальше всё в окне Ubuntu (Пуск → *Ubuntu 24.04*). Проверь, что видеокарта видна:
   ```bash
   nvidia-smi
   ```
   В таблице должна быть `NVIDIA GeForce RTX 4060`. Если `command not found` — см. «Если что-то пошло не так».

**Память для Ubuntu.** По умолчанию WSL получает половину оперативной памяти компьютера. Для экспорта в `.gguf` нужно
больше. В Windows открой Блокнот, вставь текст ниже и сохрани как `C:\Users\ТВОЁ_ИМЯ\.wslconfig` (тип файла — «Все файлы»,
без `.txt` на конце):
```ini
[wsl2]
memory=12GB
swap=16GB
```
`memory` — примерно 3/4 оперативной памяти компьютера: при 16 ГБ — `12GB`, при 32 ГБ — `24GB`. Потом в PowerShell:
`wsl --shutdown` и снова открой Ubuntu.

## Шаг 2. Программы (один раз)

```bash
sudo apt update
sudo apt install -y python3-venv python3-dev git build-essential cmake curl libcurl4-openssl-dev tmux gh
```
`cmake` и `libcurl` нужны экспорту в `.gguf` (он собирает llama.cpp), `tmux` — чтобы обучение не зависело от окна.

Нужно ~50 ГБ свободного места на диске C: (библиотеки ~10 ГБ, модель ~4 ГБ, временная 16-битная копия при экспорте ~8 ГБ,
чекпоинты, `.gguf`).

## Шаг 3. Код проекта (один раз)

Репозиторий приватный, поэтому сначала вход в GitHub:
```bash
gh auth login          # GitHub.com → HTTPS → Y → Login with a web browser: скопируй код и вставь в браузере
gh repo clone GO-igor/ishka-assistant ~/ishka-assistant
```
Код держим внутри Ubuntu (`~/ishka-assistant`), а не на диске C: (`/mnt/c/...`): так в разы быстрее.

Перед каждым новым обучением подтягивай изменения: `cd ~/ishka-assistant && git pull`.

## Шаг 4. Python и Unsloth (один раз)

```bash
python3 -m venv ~/ishka-venv
source ~/ishka-venv/bin/activate
pip install --upgrade pip
pip install unsloth openai
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```
Последняя строка должна напечатать `True NVIDIA GeForce RTX 4060`. Установка занимает 5–15 минут.

`source ~/ishka-venv/bin/activate` нужно повторять в каждом новом окне Ubuntu (в начале строки появится `(ishka-venv)`).

## Шаг 5. Подготовить Windows к долгой работе

- *Параметры → Система → Питание → Переводить в спящий режим*: **Никогда** (экран выключаться может).
- *Параметры → Центр обновления Windows → Приостановить обновления* на неделю: иначе ночью может перезагрузиться.
- Во время обучения не запускай игры и тяжёлые программы на видеокарте: им не хватит памяти, и обучение упадёт.
  Браузер можно, но он тоже занимает часть памяти видеокарты.

## Шаг 6. Замер (~15 минут)

```bash
cd ~/ishka-assistant
source ~/ishka-venv/bin/activate
./train_4060.sh bench
```
В первый раз скачается модель (~4 ГБ). Потом 5 шагов обучения, ничего не сохраняется. В конце:
```
Шаг (16 примеров): 140 с, шагов в эпохе: 203, эпоха: 8.3 ч (±10%: длина примеров разная)
Память видеокарты: обучение 5.9 ГБ + занято до запуска 0.8 ГБ (экран, браузер, служебное CUDA) из 8.0 ГБ
Эпох | обучение | + оценка каждой эпохи и экспорт | итого
  3  |  24.9 ч  |  5.0 ч |  29.9 ч ✓
Совет: 3 эпохи, запуск: ./train_4060.sh
```
(цифры здесь для примера). Пришли мне этот вывод, если сомневаешься. Если там «⚠️ Впритык» по памяти — см. ниже.

## Шаг 7. Обучение

```bash
tmux new -s ishka
cd ~/ishka-assistant && source ~/ishka-venv/bin/activate
./train_4060.sh                 # или как посоветовал замер, например: EPOCHS=2 ./train_4060.sh
```
Скрипт сам делает всё по очереди:
1. собирает и проверяет датасет (`Ошибок: 0` для трёх файлов);
2. обучает: строка `37/609 [1:20:00<20:40:00, ...]` — пройдено шагов из всех, прошло и осталось времени.
   `loss` печатается каждые 5 шагов и должен в целом уменьшаться, `eval_loss` — каждые 40. После каждой эпохи —
   «Модель после эпохи N сохранена»;
3. проверяет модель после каждой эпохи (`compare_epochs.py`) и печатает таблицу;
4. сжимает лучшую в `out/gguf/*.gguf` (q4_k_m, ~2.5 ГБ) и `Modelfile` для Ollama.

**Окно можно свернуть, но не закрывать.** Отойти от tmux, не останавливая обучение: `Ctrl+B`, затем `D`.
Вернуться: `tmux attach -t ishka`. Загрузка видеокарты: `nvidia-smi` в другой вкладке Ubuntu (около 100% — хорошо).
Журнал обучения пишется в `out/train_4060.log`.

**Если прервалось** (выключили свет, перезагрузка, ошибка) — открой Ubuntu и запусти то же самое:
```bash
cd ~/ishka-assistant && source ~/ishka-venv/bin/activate && ./train_4060.sh
```
Появится «Продолжаю с ...checkpoint-N»: потеряется не больше ~20 шагов. Готовые проверки эпох тоже не пересчитываются.
`EPOCHS` и `LORA_R` при перезапуске должны быть те же: другие значения — это другое обучение, оно начнётся с нуля
в своей папке чекпоинтов (`out/ckpt-...`), а старое останется на месте.

### Как читать таблицу сравнения

```
Модель       Вызов  После результата  Дальше в диалоге  Разговор  Разговор дальше  Отказы  Среднее
out/epoch-1  88%    87%               89%               88%       89%              3/142   88.2%
out/epoch-2  93%    92%               94%               93%       94%              2/142   93.2%
out/epoch-3  92%    91%               93%               92%       93%              1/142   92.2%
```
(цифры для примера). Колонки — те же проверки, что в Colab (раздел 6 ноутбука): выбор инструмента и аргументы, ответ
после результата инструмента, следующие сообщения в диалоге, свободный разговор и «объясни тему», отказы там, где ждали
ответ по существу. Ориентир — выше 90% в каждой колонке и отказы около нуля. Лучшая по среднему записывается в
`out/best.txt`, её и сжимает экспорт. Ошибки модели по каждой проверке — в `out/eval/epoch-N/*.txt`.
Пришли мне таблицу: если лучшей оказалась последняя эпоха и цифры ещё растут, можно попробовать 4 эпохи.

## Шаг 8. Перенести модель на Mac

Файлы лежат в Ubuntu: `~/ishka-assistant/out/gguf/`. Скопируй их на Рабочий стол Windows (`ИМЯ` — имя пользователя Windows):
```bash
cp ~/ishka-assistant/out/gguf/* /mnt/c/Users/ИМЯ/Desktop/
```
Или открой в Проводнике `\\wsl$\Ubuntu-24.04\home\` → твоя папка → `ishka-assistant\out\gguf`.
Дальше перенеси `.gguf` (и `Modelfile`, если нужна Ollama) на Mac через флешку или Google Диск и запускай как раньше:
[RUN_MAC.md](RUN_MAC.md), с шага 3 (папка `~/ishka-model`, можно переименовать файл в `ishka-Q4_K_M.gguf`).

Адаптер лучшей модели — `out/best-lora` (~250 МБ). Если на Mac модель отвечает заметно хуже, чем в таблице, сделай
`.gguf` точнее (q8_0, ~4.3 ГБ):
```bash
rm -rf out/gguf && python export.py --lora out/best-lora --quant q8_0 --no-merged
```

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| `nvidia-smi: command not found` или `False` вместо `True` на шаге 4 | обнови драйвер NVIDIA в Windows, в PowerShell: `wsl --update`, затем `wsl --shutdown`, открой Ubuntu снова. Драйвер NVIDIA внутри Ubuntu не ставь |
| `CUDA out of memory` | закрой браузер, игры, Discord; если у процессора есть встроенная графика, подключи монитор к разъёму на материнской плате. Не помогло — `LORA_R=16 ./train_4060.sh` (начнётся с нуля, модель чуть слабее). И это не помогло — пришли мне вывод замера |
| `Killed` без объяснений | Ubuntu не хватило оперативной памяти: увеличь `memory`/`swap` в `.wslconfig` (шаг 1), `wsl --shutdown`, запусти снова |
| `Не найден Unsloth` | забыли `source ~/ishka-venv/bin/activate` |
| `Python.h: No such file` | `sudo apt install -y python3-dev` |
| экспорт падает на сборке llama.cpp (`cmake`, `curl`) | пакеты из шага 2, затем `./train_4060.sh` снова: обучение и проверки уже готовы, через пару минут дойдёт до экспорта |
| шаг дольше 400 с | `nvidia-smi`: в списке процессов должен быть `python`, загрузка около 100%. В Windows: *Питание → Режим питания → Максимальная производительность* |
| «Пропускаю недописанный чекпоинт» | нормально после внезапного выключения: берётся предыдущий |
| `Ошибок: N` при проверке датасета, `Проверка не прошла` | пришли мне вывод |
